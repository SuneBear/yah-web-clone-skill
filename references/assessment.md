# 复杂度、模式与忠实度闸门

## 模式

| 模式 | 目标 | 默认边界 |
|---|---|---|
| `full` | 1:1 镜像 + 中文解构 + 可运行效果实验室 | `site/` 不被 GUI 或教学代码污染 |
| `mirror` | 只保存原布局、内容、资产、交互和响应式 | 不生成分析、Preset 或重建代码 |
| `effect` | 只忠实复刻一个指定效果 | 不顺手复制无关页面；默认 Preset 对应原版 |

用户说“完整克隆并分析”时使用 `full`；明确说“只缓存”时使用 `mirror`；只要单个特效时使用 `effect`。品牌改造不属于这三个模式，应另开适配任务。

## 复杂度 L1-L6

| 等级 | 类型 | 典型信号 | 关键风险 |
|---|---|---|---|
| L1 | 静态 HTML/CSS | 少量 JS、页面少 | 字体、外链和资源路径 |
| L2 | 多页面/CMS 前台 | 多路由、表单、内容数据 | 路由覆盖和远程媒体 |
| L3 | React/Vue/Next 前端 | hydration、chunk、RSC/API | 静态托管与深层路由 |
| L4 | 动画品牌站 | GSAP、Lenis、视频、滚动时间线 | 时序和关键状态 |
| L5 | WebGL/Canvas/WebGPU | Shader、物理、后处理、二进制资源 | GPU 状态、运行时资源和性能 |
| L6 | 登录/支付/数据系统 | 权限、账号、搜索推荐 | 服务端能力无法仅靠前端镜像 |

## 1:1 声明闸门

以下各项都需要证据：

| 维度 | 通过条件 |
|---|---|
| 来源 | GitHub commit、source map、部署清单或运行时捕获已登记 |
| 结构 | 主要路由、区块顺序、文案和滚动高度一致 |
| 视觉 | 桌面、平板、手机关键截图已对照 |
| 状态 | top/middle/bottom、hover/click/drag/scroll 等关键状态已覆盖 |
| 渲染 | Canvas/WebGL/WebGPU 确实运行，不是静态占位 |
| 响应式 | 配置中的所有 viewport 已验证 |
| 功能 | 导航、媒体、深层路由和必要 fixture 可用 |
| 稳定性 | console/page error 为 0，或错误已明确解释 |
| 部署 | 生产域名对应已验证的同一提交/构建 |

只有单张首屏、主观“看起来像”或 console 无错误，不足以声明 1:1。

## 评分

每项 0-5 分，并附证据路径：

- 源证据
- 路由覆盖
- 结构保真
- 视觉保真
- 动效/交互
- 响应式
- 功能完整
- 离线完整度
- 部署一致性

报告中同时列出未覆盖状态和已知缺口，不用总分掩盖关键失败。
