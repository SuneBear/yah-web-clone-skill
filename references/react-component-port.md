# 从网页效果移植为 React 组件

本分支参考 [Compronents 的 PAGE-PORTS.md](https://github.com/kiritocode1/compronents/blob/main/PAGE-PORTS.md) 的来源阅读、素材整理、CSS 作用域、生命周期移植与逐项验收方法。这里只提炼工作流；具体目录、组件 API、打包方式和素材存储由目标项目决定，不套用对方的 Vercel Blob、shadcn Registry 或品牌约定。

## 适用边界

用户明确需要可复用 React 组件时，在 `effect` 模式或 `full` 模式的指定效果上执行。用户只要原站镜像、可运行的纯 HTML/JS 实验，或尚未确认 React 宿主时，不强行移植。整页模板也可用同一流程，但必须按其路由、滚动容器和页面切换扩展验收矩阵。

组件移植是现有 `RAW REPLAY → BASELINE → PROJECTIZE` 的后续工程化步骤，不代替来源发现或 baseline。`full` 的 `site/` 继续作为原站镜像；React 源码与独立预览放在 `lab/` 或用户指定的现有组件仓库。不要用 iframe 包装镜像冒充可编辑组件；若因隔离需求只能使用 iframe，明确标为嵌入式镜像并说明 API 边界。

## 移植步骤

1. **固定来源和行为契约。** 读原页面、样式、脚本、依赖与素材，记录来源 URL、revision/hash、框架和证据等级；列出效果的触发、输入、时序、视口、状态和默认值。先让最小原样 baseline 可运行并与原站对照。历史缓存只与其对应版本对照，无法取得当前原站时说明边界。
2. **收拢资源。** 建一份素材清单，保留原字体、图片、视频、模型与 shader 的路径关系；根据用户项目选择本地资产、已有 CDN 或对象存储。更改资源地址后检查字体加载、跨域媒体、Canvas/WebGL 纹理和离线依赖。不要把外部项目的素材上传方案当作默认要求。
3. **限定样式与 DOM。** 将选择器限制在组件根节点，处理 `html`、`body`、`*`、`@font-face`、keyframes 和根相对 `url(...)`。解析 CSS 时注意字符串、括号和字体 URL 中的分号。查询 DOM 时从根 ref 出发；多个实例或过渡层同时存在时不得误选别的实例。
4. **移入 React 生命周期。** 把初始化放进 effect/合适的框架钩子，卸载时清除事件、计时器、动画帧、GSAP/ScrollTrigger、观察器、音频、WebGL 纹理和渲染器。避免每次 render 重建引擎。滚动效果从实际容器解析 scroller，不假定是 `window`；页面过渡与加载遮罩要保留其真实进入/退出状态。
5. **设计最小组件 API。** 暴露效果真正需要的内容、默认参数、素材基址、尺寸/容器和 `className`/`style` 等入口；保留与原站一致的默认值。额外调参和 Preset 明确标为派生项。若用户要求可安装组件，再按目标项目的注册格式连接 demo、预览、编辑器和依赖声明；普通 React 组件不必创建 Registry。
6. **逐项验收。** 在真实宿主页面同时验证单实例、多实例、卸载后重挂、交互、响应式、字体/素材、console/page error 和性能。按效果选择截图、多帧或录屏对照；运行项目现有的类型检查、lint、构建，再访问实际预览路由确认资源和样式。记录原版与移植版差异，不把“能编译”当作视觉验收。
